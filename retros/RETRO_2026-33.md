## Four questions

### What shipped that I'm glad about

**#176 — agents could never read the knowledge base.** The Compiled-KB gate shipped *on* while `approved_paths()` was empty on all six PKB roots, so `pkb.search()` short-circuited to `[]` before searching. Buddy had never once retrieved from the KB, across 540 source documents. Post-fix and post-backfill, the operator's `ai` World went from 0 approved pages to 339, and `"how does attention work"` returns 12 semantic hits topped by `attention.md`.

This was a win **because of** the process, not in spite of it. The instinct was "the fix looks small" — and it was, mechanically. Routing it through architect design instead surfaced that the obvious hook point (seal time) was *unreachable*: term pages don't exist at seal time, they're synthesized at mount. A seal-time hook would have passed its own tests and fixed zero of six roots. The one-line version of this fix would have shipped a no-op.

### What didn't ship that I expected to

**Nothing was blocked — but the persistence sprint cost ~5× its estimate**, and the reason is worth recording. It ran five build rounds, three architect reviews, and three QA passes. Every single round found something real; not one was a stylistic quibble. The defects clustered in one place: **the layer that reports whether things work.**

`status.sh`'s DB collector ended in `2>/dev/null || echo '{}'`. The lossy-migration classifier's docstring claimed it "fails closed, never open" while four executable bypasses existed. A predicate returning the wrong *type* silenced every other provisioning check. And most consequentially, **the CLI drivers were testing `main`'s source tree**, so every green driver result across three review rounds meant nothing until QA caught it.

The block was in **the work**, not the process. But it was the *same defect* recurring at every layer — which is itself the finding.

### What I learned

**When a mechanism ships behind a step that nothing performs, the bug is invisible to every test that tests the mechanism.** Three consecutive releases did this: QA-6 (gate on, nothing ever approved), defect A (store shipped, nothing ever created it), defect B (retrieval died silently while four diagnostics reported healthy). Each mechanism was individually correct and individually tested.

Action-shaped: **when adding a mechanism that requires instantiation, write the "declared but not instantiated" assertion in the same commit as the mechanism.** That is now structural rather than aspirational — `src/arail/provisioning.py` encodes *declared and not instantiated ⇒ always a finding*, and it would have caught all three.

Second, narrower learning, worth `/learn` on its own: **a green test tells you nothing until you have verified which source tree it loaded.** `make_fake_venv` symlinks the discovered venv's site-packages, and the only venv on the machine was the main checkout's editable install pointing at `main`. Worktree-based review is structurally exposed to this; CI (`pip install -e .` in-checkout) is not.

### One concrete change for next week

**Wire every persona-produced shell/CLI driver into CI in the same sprint that creates it — never as filed debt.**

This week produced the evidence. The architect promoted the CI-runnable driver path from debt to a *merge blocker*, and on its first real run that wiring found six defects nothing else was going to find: a Linux-only test assumption, a documented first-run path that left `doctor` degraded, a vacuous security assertion (`stat -f` failing on Linux, silently dropping the `0600` check), a Gentoo supervision-reporting bug, an under-scoped gate predicate, and an over-strict smoke assertion. All six were sitting in code that had only ever run on developer macOS.

One change, not a list: **a driver that isn't in a workflow file doesn't count as written.**

**One real slip, and it wasn't a persona:** a builder used a bare `git stash`/`stash pop` mid-build, which popped an unrelated stash from another branch and briefly conflicted ~350 `lab/` files. Recovered cleanly; no `lab/` change reached any commit; all 19 stash entries intact, verified independently at every subsequent handoff. The corrective (explicit paths only, never a bare stash) was issued and held for the remaining four rounds.

**Drift risk to name while it's one week old:** this week's two sprints ran **8 build rounds between them**. The pipeline is designed for build → review → test with loop-backs as the exception. Eight is not an exception; it's the mode. It worked — every round found something real — but a sprint that needs five build rounds may be a sprint whose spec was underspecified, and that question belongs to the architect at design time, not to the reviewer at round four.
